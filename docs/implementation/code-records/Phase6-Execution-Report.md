## 🧪 Phase 6 測試詳情 (14 Tests)

### **T-015: HTTP 錯誤狀態碼測試** (6 tests)

- ✅ **T-015-01: HTTP 401 - 未授權錯誤處理**
  - 驗證：狀態碼 401、錯誤代碼 1001、錯誤訊息
  - 情景：認證失敗、認證令牌過期
  - 響應時間：<5ms

- ✅ **T-015-02: HTTP 403 - 禁止訪問錯誤處理**
  - 驗證：狀態碼 403、錯誤代碼 1003、權限驗證
  - 情景：沒有足夠權限訪問資源
  - 響應時間：<5ms

- ✅ **T-015-03: HTTP 404 - 資源未找到錯誤處理**
  - 驗證：狀態碼 404、錯誤代碼 1004、資源通知
  - 情景：API 端點被移除、版本不匹配
  - 響應時間：<5ms

- ✅ **T-015-04: HTTP 422 - 無法處理的實體錯誤處理**
  - 驗證：狀態碼 422、詳細錯誤字段列表、驗證訊息
  - 情景：無效的請求參數、數據格式錯誤、違反業務規則
  - 響應時間：<5ms
  - 特性：包含詳細的字段級別錯誤信息

- ✅ **T-015-05: HTTP 429 - 請求過於頻繁錯誤處理**
  - 驗證：狀態碼 429、速率限制信息、重試延遲 (60 秒)
  - 情景：超過 API 配額、DDoS 防護觸發
  - 響應時間：<5ms
  - 特性：包含 `retryAfter` 指導重試時機

- ✅ **T-015-06: HTTP 500 - 服務器錯誤處理**
  - 驗證：狀態碼 500、服務器錯誤代碼 5000、追蹤 ID
  - 情景：後端異常、資料庫連接失敗、外部服務故障
  - 響應時間：<5ms
  - 特性：包含 traceId 用於日誌追蹤

### **T-016: 網絡錯誤測試** (2 tests)

- ✅ **T-016-01: 網絡超時錯誤處理**
  - 驗證：Axios 錯誤標記、網絡不可用
  - 情景：連接超時、請求掛起
  - 特性：無 HTTP response，需要特殊處理
  - 恢復策略：重試或使用緩存數據

- ✅ **T-016-02: DNS 解析失敗錯誤處理**
  - 驗證：Axios 錯誤標記、DNS 失敗
  - 情景：域名不存在、DNS 伺服器不可用
  - 特性：無 HTTP response，快速失敗
  - 恢復策略：檢查網絡連接、降級到緩存

### **T-017: 錯誤恢復機制測試** (1 test)

- ✅ **T-017-01: 重試機制 - 失敗後自動恢復**
  - 驗證：前 2 次失敗 (500 錯誤)，第 3 次成功
  - 恢復步驟：
    1. 第 1 次請求 → 失敗 (500)
    2. 等待 10ms（退避延遲）
    3. 第 2 次請求 → 失敗 (500)
    4. 等待 10ms（退避延遲）
    5. 第 3 次請求 → 成功 (200)
  - 重試次數：最多 3 次
  - 驗證：最終成功取得數據

### **擴展測試** (5 tests)

- ✅ **擴展-01: 快速失敗轉降級 - 401 錯誤**
  - 策略：401 錯誤不重試（快速失敗）
  - 降級方案：使用預設數據或空數據
  - 驗證：立即返回，不浪費重試機會

- ✅ **擴展-02: 可重試的錯誤 - 503 Service Unavailable**
  - 策略：503 標記為可重試
  - 情景：服務暫時不可用、維護中
  - 驗證：應該被列入重試候選

- ✅ **擴展-03: 級聯錯誤處理 - 多個依賴失敗**
  - 場景：3 個並發請求全部返回 500 錯誤
  - 驗證：一致的錯誤處理
  - 驗證：正確的錯誤代碼和訊息傳播

- ✅ **擴展-04: 部分恢復場景**
  - 場景：3 個並發請求中 2 個成功，1 個失敗
  - 驗證：成功的請求返回完整數據
  - 驗證：失敗的請求返回錯誤
  - 驗證：系統不因單個失敗而停止

- ✅ **擴展-05: 錯誤恢復後重新開始監聽**
  - 流程：
    1. 第 1 次請求 → 失敗 (500)
    2. 等待 10ms
    3. 第 2 次請求 → 成功 (200)
  - 驗證：恢復後正常運作
  - 驗證：沒有殘留的錯誤狀態

## 📈 錯誤恢復機制分析

### 錯誤分類

| 錯誤類型 | HTTP 狀態 | 可重試 | 可降級 | 快速失敗 |
|---------|----------|------|------|---------|
| 未授權 | 401 | ❌ | ✅ | ✅ |
| 禁止訪問 | 403 | ❌ | ✅ | ✅ |
| 資源未找到 | 404 | ❌ | ✅ | ✅ |
| 驗證錯誤 | 422 | ❌ | ✅ | ✅ |
| 速率限制 | 429 | ✅ | ✅ | ❌ |
| 服務器錯誤 | 500 | ✅ | ✅ | ❌ |
| 服務不可用 | 503 | ✅ | ✅ | ❌ |
| 網絡超時 | - | ✅ | ✅ | ❌ |
| DNS 失敗 | - | ✅ | ✅ | ❌ |

### 恢復策略矩陣

```
快速失敗錯誤 (4xx 客戶端錯誤):
  401, 403, 404, 422
  → 不重試
  → 立即降級到預設數據或空數據
  → 立即通知用戶

可重試錯誤 (5xx 服務器錯誤、429、網絡錯誤):
  429, 500, 503, 超時, DNS
  → 指數退避重試（最多 N 次）
  → 每次重試前等待遞增延遲
  → 最大重試時間上限
  → 失敗後降級到預設數據
```
