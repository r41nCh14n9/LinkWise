## 執行摘要

LinkWise 是一個企業級 B2B 採購 SaaS 平台，通過集中化的儀表板、精細的權限管理、完整的供應商生命週期管理，以及智能的採購流程，幫助企業簡化採購操作、降低成本、提升效率。

**核心價值主張：**
- 🎯 統一的採購視圖（Dashboard）
- 🔐 企業級權限管理（RBAC）
- 🤝 供應商全生命週期管理（VMS）
- 📋 自動化採購流程（PR/PO）

**第一階段目標**: 交付一個可用的採購平台核心，支持 1,000 家企業初期使用。

## 需求優先級與範圍

### P1: 儀表板 (Dashboard)
**業務價值**: 高 | **實現複雜度**: 中 | **依賴項**: RBAC、PR/PO、VMS  

**核心訴求**:
- 企業採購決策者需要快速了解採購健康狀態
- 需要實時監控關鍵指標（支出趨勢、供應商表現、待決PR等）

**預期功能**:
```
儀表板頁面結構:
├─ 上方摘要卡片
│  ├─ 月度總支出 (主要KPI)
│  ├─ 活躍供應商數 (VMS關鍵指標)
│  ├─ 待處理PR數 (流程阻塞指標)
│  └─ 庫存預警數 (風險指標)
│
├─ 中央圖表區域
│  ├─ 支出趨勢圖 (最近6個月柱狀圖)
│  ├─ 供應商評分分佈 (供應商風險熱力圖)
│  └─ PR/PO流程分佈 (轉換漏斗)
│
└─ 下方快速操作區
   ├─ 最近操作的PR (列表)
   ├─ 高風險供應商 (快速預警)
   └─ 待審批清單 (優先任務)
```

### P2: 帳號權限管理 (RBAC)
**業務價值**: 高 | **實現複雜度**: 高 | **依賴項**: Keycloak、身份驗證系統  

**核心訴求**:
- 不同角色應有不同的功能可見性和操作權限
- 企業級支持按部門維度的權限精細化管理

**角色體系**:

| 角色 | 典型職位 | 主要權限 | 儀表板查看 |
|------|--------|--------|----------|
| **Admin** | IT/採購總監 | 全系統管理、用戶管理、角色配置、系統設置 | 企業全景 |
| **Approver** | 部門經理/主管 | 審批PR、查看部門/企業報表、管理部門供應商 | 部門維度 |
| **Buyer** | 採購人員 | 創建/編輯PR、查詢供應商、提交訂單 | 自己和下屬數據 |
| **Requester** | 業務部門員工 | 創建PR請求、查詢訂單狀態 | 自己的請求 |

**帳號管理需求**:

1. **身份驗證支持**:
   - Google OAuth 2.0 (推薦用於初期用戶)
   - Keycloak 企業帳戶集成 (支持企業 SSO)
   - 本地帳號創建 (初期備用)

2. **組織結構管理**:
   - 支持多層級部門結構
   - 每個部門可配置主管
   - 用戶與部門之間的關聯

3. **權限粒度**:
   - 功能級別: 儀表板查看、PR/PO 操作、VMS 管理
   - 數據級別: 部門數據隔離、跨部門查看權限控制
   - 操作級別: 創建、讀取、更新、刪除

### P3: 供應商管理系統 (VMS)
**業務價值**: 中 | **實現複雜度**: 高 | **依賴項**: RBAC  

**核心訴求**:
- 供應商是採購的核心，需要完整的生命週期管理
- 需要風險評估和績效監控

**供應商狀態流轉**:

```
狀態機設計:
未認識 → 洽談中 → 待審核 → Onboarding → Active → 風險監控 → 降級/中止
                      ↓
                   駁回 → 改善中
```

**VMS 功能模塊**:

1. **供應商檔案 (Vendor Profile)**:
   - 基本信息: 公司名稱、聯絡人、資質證書
   - 地理位置: 主要生產地、配送能力
   - 財務信息: 銀行賬戶、發票地址
   - 能力矩陣: 提供產品/服務分類

2. **風險評級系統 (Risk Assessment)**:
   ```
   評分維度:
   ├─ 財務健康度 (Financial Health) - 40%
   ├─ 交付能力 (Delivery Performance) - 30%
   ├─ 質量表現 (Quality Record) - 20%
   └─ 合規狀態 (Compliance) - 10%
   
   風險等級:
   ├─ 綠色 (Green): 85-100 分
   ├─ 黃色 (Yellow): 70-84 分
   └─ 紅色 (Red): <70 分
   ```

3. **績效追蹤 (Performance Tracking)**:
   - 準時交付率 (On-time Delivery %)
   - 質量缺陷率 (Defect Rate %)
   - 價格穩定性 (Price Consistency)
   - 反應時間 (Response Time)

4. **Onboarding 流程**:
   ```
   Onboarding 檢查清單:
   ├─ □ 營業執照驗證
   ├─ □ 資格證書審核
   ├─ □ 銀行信息確認
   ├─ □ 簽署協議
   ├─ □ 系統帳號創建
   └─ □ 試單完成
   ```

---

### P4: 採購流程 (PR/PO)
**業務價值**: 高 | **實現複雜度**: 高 | **依賴項**: RBAC、VMS  

**核心訴求**:
- 從申請到採購的全流程自動化
- 清晰的狀態追蹤和審批流

**PR/PO 狀態流轉**:

```
購買申請流程 (PR → PO):

PR (Purchase Request)
├─ 新建 (Draft)
├─ 已提交 (Submitted)
├─ 待一級審批 (Approval L1)
├─ 待二級審批 (Approval L2) [Optional]
├─ 已批准 (Approved)
│  └─ 轉換為 PO (Convert to PO)
│
└─ 駁回流程:
   ├─ 一級駁回 (Rejected L1) → 修改後重新提交
   └─ 二級駁回 (Rejected L2) → 修改後重新提交

PO (Purchase Order)
├─ 已下達 (Issued)
├─ 供應商已確認 (Acknowledged)
├─ 部分收貨 (Partially Received)
├─ 已收齊 (Fully Received)
├─ 已開票 (Invoiced)
└─ 已結案 (Closed)
```

**PR 創建表單**:
```
必填字段:
├─ 申請人 (Requester) [自動填充]
├─ 申請部門 (Department) [自動填充]
├─ 採購類別 (Category)
├─ 供應商 (Vendor) - 下拉選擇
├─ 預算科目 (Budget Code)
├─ 物料/服務 (Item Description)
├─ 數量 (Quantity)
├─ 單價 (Unit Price)
├─ 需要日期 (Required Date)
└─ 商業條款 (Payment Terms)

可選字段:
├─ 附件 (Attachments)
├─ 備註 (Notes)
└─ 成本中心 (Cost Center)

計算字段:
├─ 小計 (Subtotal) = 數量 × 單價
├─ 稅金 (Tax) [可配置]
└─ 總額 (Total)
```

**審批規則引擎**:
```
審批路由規則:
├─ 金額 < 5,000: 直接通過 (Auto-Approve)
├─ 5,000 ≤ 金額 < 50,000: 部門主管審批 (L1)
├─ 50,000 ≤ 金額 < 500,000: 部門主管 + 採購總監 (L1 + L2)
└─ 金額 ≥ 500,000: 部門主管 + 採購總監 + 財務總監 (L1 + L2 + L3)

審批超時:
├─ L1 超時 24 小時: 自動升級 L2
├─ L2 超時 24 小時: 自動升級 L3
└─ L3 超時 48 小時: 發送警告郵件
```

## 用戶群體分析

### 用戶畫像

**用戶群體 1: 採購經理 (Buyer Manager)**
- 職責: 日常採購操作、供應商管理、報表分析
- 月活躍場景: 創建 50-200 個 PR、審批 100-300 個流程
- 關鍵訴求: 快速創建 PR、實時看到審批進度、供應商績效對比
- 典型工作流:
  ```
  登入系統 → 查看待審批清單 → 審批 PR → 查詢供應商績效 → 生成月度報表
  ```

**用戶群體 2: 部門主管 (Approver)**
- 職責: 審批下屬 PR、監控部門採購支出
- 月活躍場景: 審批 50-100 個 PR、查看部門儀表板
- 關鍵訴求: 清晰的審批通知、快速的批量審批、部門支出監控
- 典型工作流:
  ```
  郵件/系統通知 → 查看待審批 → 批量審批或逐一審批 → 返回部門儀表板
  ```

**用戶群體 3: 業務員工 (Requester)**
- 職責: 提交採購需求
- 月活躍場景: 創建 1-20 個 PR、查詢訂單狀態
- 關鍵訴求: 簡單的表單填寫、清晰的流程狀態
- 典型工作流:
  ```
  填寫 PR 表單 → 提交 → 在儀表板查看審批進度
  ```

**用戶群體 4: 系統管理員 (Admin)**
- 職責: 系統配置、用戶管理、數據維護
- 月活躍場景: 用戶管理、系統設置、數據備份
- 關鍵訴求: 完整的系統控制面板、日誌和審計功能
- 典型工作流:
  ```
  進入管理後台 → 管理用戶和角色 → 配置系統參數 → 查看系統日誌
  ```

### 1. 儀表板功能模塊 (P1)

#### 1.1 摘要卡片
```
【月度總支出】
數值: ¥1,234,567.89 (增長率: +12.3%)
下鑽: 點擊進入支出詳情報表

【活躍供應商】
數值: 47 家 (新增: 3 家)
下鑽: 點擊進入供應商列表

【待處理 PR】
數值: 12 個 (逾期: 2 個)
下鑽: 點擊進入待審批清單

【庫存預警】
數值: 5 項 (紅色警告: 1 項)
下鑽: 點擊進入預警詳情
```

**功能需求**:
- [ ] FR-D1.1: 自動計算月度總支出（按部門、供應商、類別聚合）
- [ ] FR-D1.2: 實時展示活躍供應商數量及變化趨勢
- [ ] FR-D1.3: 動態計算待處理 PR 數量（含逾期標記）
- [ ] FR-D1.4: 集成庫存模塊預警數據

#### 1.2 支出趨勢圖表
```
圖表類型: 柱狀圖 + 折線圖
X 軸: 月份 (最近 12 個月 或 6 個月)
Y 軸: 支出金額 (CNY)
柱狀: 各月總支出
折線: 環比增長率

交互: 懸停顯示具體數值、點擊鑽取到日期範圍內的 PR 詳情
```

**功能需求**:
- [ ] FR-D2.1: 支持 6 個月、12 個月時間範圍切換
- [ ] FR-D2.2: 支持按供應商維度過濾
- [ ] FR-D2.3: 支持按類別維度過濾
- [ ] FR-D2.4: 支持導出數據至 Excel

#### 1.3 供應商評分熱力圖
```
縱軸: 供應商名稱 (Top 20)
橫軸: 評分維度 (財務、交付、質量、合規)
顏色: 綠/黃/紅 (風險等級)

交互: 點擊供應商進入詳情頁
```

**功能需求**:
- [ ] FR-D3.1: 實時計算供應商綜合評分
- [ ] FR-D3.2: 按風險等級篩選供應商
- [ ] FR-D3.3: 查看評分歷史變化

#### 1.4 PR/PO 流程分佈 (漏斗圖)
```
漏斗層級:
草稿 (Draft) → 已提交 (Submitted) → 待審批 → 已批准 → 已下達 PO → 已結案

展示: 各階段 PR 數量、轉化率
```

**功能需求**:
- [ ] FR-D4.1: 實時更新各階段 PR/PO 數量
- [ ] FR-D4.2: 計算各轉換環節的轉化率
- [ ] FR-D4.3: 高亮顯示流程瓶頸

#### 1.5 最近操作清單
```
表格列:
├─ PR 編號 (ID)
├─ 供應商
├─ 金額
├─ 狀態
├─ 最後更新時間
└─ 操作按鈕 (查看、編輯)
```

**功能需求**:
- [ ] FR-D5.1: 展示最近 10-20 條 PR 記錄
- [ ] FR-D5.2: 支持快速搜索和過濾
- [ ] FR-D5.3: 一鍵進入詳情頁

### 2. 帳號權限管理功能模塊 (P2)

#### 2.1 身份驗證系統

**功能需求**:
- [ ] FR-R1.1: 支持 Google OAuth 2.0 登錄流程
  ```
  用戶點擊【Google 登入】→ 重定向到 Google 授權頁 → 驗證身份 → 返回系統
  系統自動創建用戶檔案（基於 Google 郵箱域名識別企業）
  ```

- [ ] FR-R1.2: 支持 Keycloak 企業帳號集成
  ```
  集成點: 使用 Keycloak 提供的 OIDC 端點
  流程: Keycloak 驗證 → JWT Token 返回 → 系統使用 Token 進行後續操作
  ```

- [ ] FR-R1.3: 支持本地帳號創建（備用方案）
  ```
  表單字段: 郵箱、密碼（加鹽 bcrypt）、部門、角色
  初期仅 Admin 可創建本地帳號
  ```

- [ ] FR-R1.4: 會話管理
  ```
  Token 有效期: 1 小時 (Access Token) / 7 天 (Refresh Token)
  單點登出: 用戶登出時清除 Token
  超時自動跳轉: 會話過期自動跳轉到登入頁
  ```

#### 2.2 用戶管理介面

**功能需求**:
- [ ] FR-R2.1: 用戶列表頁面
  ```
  表格欄位:
  ├─ 用戶名 / 郵箱
  ├─ 部門
  ├─ 角色
  ├─ 狀態 (激活 / 禁用)
  ├─ 最後登入時間
  └─ 操作 (編輯 / 禁用 / 刪除)
  
  搜索 / 篩選: 按部門、角色、狀態
  ```

- [ ] FR-R2.2: 創建用戶
  ```
  表單:
  ├─ 郵箱 *
  ├─ 姓名 *
  ├─ 部門 * (下拉)
  ├─ 角色 * (可多選: Admin, Approver, Buyer, Requester)
  ├─ 直屬主管 (Requester 和 Buyer 需填)
  └─ 備註
  
  驗證: 郵箱唯一性、部門存在性
  成功後: 向用戶發送初始化郵件 (Google/Keycloak SSO 鏈接)
  ```

- [ ] FR-R2.3: 編輯用戶
  ```
  允許編輯: 部門、角色、直屬主管、狀態
  不允許編輯: 郵箱 (唯一標識)
  編輯後: 記錄操作日誌
  ```

- [ ] FR-R2.4: 禁用 / 刪除用戶
  ```
  禁用: 用戶不能登入，但保留歷史數據
  刪除: 標記為軟刪除，隱藏用戶信息，保留審計日誌
  ```

#### 2.3 角色和權限配置

**功能需求**:
- [ ] FR-R3.1: 角色管理
  ```
  預設角色 (系統內置，不可修改):
  ├─ Admin: 全系統權限
  ├─ Approver: 審批權限 + 報表查看
  ├─ Buyer: 採購操作 + 供應商查詢
  └─ Requester: 基礎申請 + 查詢自己的 PR
  
  自定義角色: 支持 Admin 創建自定義角色組合
  ```

- [ ] FR-R3.2: 權限矩陣
  ```
  權限維度:
  ├─ 模塊級別 (Dashboard, RBAC, VMS, PR/PO)
  ├─ 功能級別 (查看, 創建, 編輯, 刪除, 審批)
  ├─ 數據級別 (企業級, 部門級, 個人級)
  └─ 操作級別 (CRUD + 審批動作)
  
  權限映射表示例:
  角色 Admin:
    - Dashboard: 查看 (企業級)
    - RBAC: 全部 (企業級)
    - VMS: 全部 (企業級)
    - PR/PO: 全部 (企業級)
  
  角色 Buyer:
    - Dashboard: 查看 (部門級)
    - PR/PO: 創建, 編輯, 查詢 (部門級)
    - VMS: 查詢 (部門級)
  ```

- [ ] FR-R3.3: 部門維度權限
  ```
  部門隔離:
  ├─ 用戶只能查看自己部門的數據
  ├─ 可配置跨部門查看權限 (由 Admin 設置)
  └─ 部門主管可見下屬部門數據 (可選)
  
  示例:
  - Buyer 在 採購部: 只看到採購部的 PR
  - Buyer 在 IT: 只看到 IT 部門的 PR
  - Admin: 看到所有部門的 PR
  ```

#### 2.4 組織結構管理

  展示方式: 樹狀結構圖

### 3. 供應商管理系統功能模塊 (P3)

#### 3.1 供應商檔案管理

**功能需求**:

## 非功能需求規範

### NFR-1: 性能需求

| 指標 | 目標值 | 說明 |
|------|-------|------|
| 頁面首屏加載 (FCP) | < 2 秒 | 用戶感知響應速度 |
| 完全加載時間 (LCP) | < 4 秒 | 包括圖表、列表完全渲染 |
| 表格查詢響應時間 | < 500 ms | 列表、搜索、篩選 |
| 圖表渲染時間 | < 1 秒 | Dashboard 儀表板圖表 |
| API 平均響應時間 | < 200 ms | 95% 請求滿足 |
| 數據庫查詢時間 | < 100 ms | 單次查詢 (含索引優化) |
| 並發用戶支持 | 500+ 同時在線 | SaaS 單區域系統 |
| 日請求量 | 100,000+ 次 | 1,000 家企業 × 100 用戶平均 |
| 登入響應時間 | < 2 秒 | OAuth / Keycloak 集成 |

**實現策略**:
- 前端: Vite 打包優化、代碼分割、懶加載
- 後端: 數據庫索引、查詢優化、緩存策略 (Redis)
- 基礎設施: CDN 分發靜態資源、多個 Nginx 工作進程

### NFR-2: 安全性需求

| 需求 | 要求 |
|------|------|
| 身份驗證 | 支持 OAuth 2.0 (Google) 和 OIDC (Keycloak) 及本地帳號 |
| 傳輸加密 | HTTPS 全站 (TLS 1.2+) |
| 密碼存儲 | 本地帳號密碼需加鹽加密 |
| 會話管理 | Token-based 會話，支持自動過期 |
| 數據隔離 | 多租戶企業級隔離，部門級數據權限控制 |
| 敏感數據 | 銀行賬戶、財務信息等需加密存儲 |

### SA-2: 用戶場景 Use Case 分析

**Use Case 1: 採購人員創建和提交 PR**
```
參與者: Buyer (採購人員)
前置條件: 已登入系統

主流程:
1. Buyer 進入 PR 創建頁面
2. 填寫 PR 表單 (供應商、物料、數量、金額等)
3. 選擇上傳附件 (可選)
4. 點擊【提交】
5. 系統驗證表單
6. 系統根據金額自動判斷審批路由
7. 系統發送審批通知給相關審批人
8. Buyer 收到系統確認訊息
9. Use Case 結束

異常流程:
- 表單驗證失敗 → 返回錯誤提示，Buyer 修正後重新提交
- 供應商不存在 → 提示 Buyer 先註冊供應商
- 超出部門預算 → 提示警告但允許繼續提交
```

**Use Case 2: 部門主管審批 PR**
```
參與者: Approver L1 (部門主管)
前置條件: 已登入系統、有待審批的 PR

主流程:
1. 系統在登入後顯示待審批通知
2. Approver 進入待審批清單
3. 選擇一個 PR，查看詳情
4. 分析 PR 信息、供應商信息、相關風險
5. 填寫審批意見
6. 點擊【批准】或【駁回】
7. 系統記錄審批決策和時間
8. 系統發送通知給 Buyer 和下一審批人 (如有)
9. Use Case 結束

異常流程:
- 遇到疑問 → Approver 可轉委託給其他同級審批人
- 需要補充信息 → 駁回給 Buyer 要求修改
- 超時未審批 → 系統自動升級至 L2
```

**Use Case 3: 系統管理員管理用戶和權限**
```
參與者: Admin (系統管理員)
前置條件: 已登入系統

主流程:
1. Admin 進入系統管理後台
2. 進入用戶管理模塊
3. 查看用戶列表、搜索特定用戶
4. 點擊【新增用戶】
5. 填寫用戶信息 (郵箱、姓名、部門、角色)
6. 系統發送初始化郵件給用戶
7. 用戶點擊郵件鏈接，選擇登入方式 (Google / Keycloak)
8. 用戶首次登入成功
9. Admin 在系統中確認用戶激活
10. Use Case 結束

異常流程:
- 郵箱已被使用 → 系統提示重複，Admin 選擇編輯或刪除舊用戶
- 部門不存在 → Admin 先創建部門後重試
```
