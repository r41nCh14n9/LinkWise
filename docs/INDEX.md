# LinkWise Documentation Hub

Welcome to LinkWise documentation! This folder contains all project-specific documentation, guidelines, and outputs generated by our 7-Agent system.

---

## 📚 Documentation Structure

### 🎯 [reference/](./reference/) - Foundation Materials

**Purpose:** Single source of truth for all project standards and guidelines. Consumed by ALL agents.

- **[guidelines/](./reference/guidelines/)** - Project technical standards
  - Coding conventions, tech stack, development workflow
  - Performance and security guidelines
  
- **[templates/](./reference/templates/)** - Reusable code templates
  - Component templates, service templates, test templates
  
- **[examples/](./reference/examples/)** - Reference implementations
  - [good/](./reference/examples/good/) - Best practice examples
  - [anti-patterns/](./reference/examples/anti-patterns/) - What to avoid
  
- **[requirements/](./reference/requirements/)** - Project requirements (input for agents)

---

### 📋 [plans/](./plans/) - Plan Agent Output

Generated by `/plan` command. Contains project planning materials.

- **[active/](./plans/active/)** - Current active plans
- **[completed/](./plans/completed/)** - Archived/historical plans
- **[templates/](./plans/templates/)** - Plan templates for reuse

---

### 📊 [analysis/](./analysis/) - SA Agent Output

Generated by `/sa` command. Requirements and system analysis documentation.

- **[requirements/](./analysis/requirements/)** ⭐ **Mandatory Output**
  - Functional requirements analysis
  - Non-functional requirements documentation
  - Requirements specification documents
  
- **[system-analysis/](./analysis/system-analysis/)** - Optional Output
  - Only created when analyzing existing systems (integration/legacy scenarios)
  - System architecture analysis and design decisions

---

### 🏗️ [design/](./design/) - SD Agent Output

Generated by `/sd` command. System design and architecture documentation.

- **[architecture/](./design/architecture/)** - System architecture design
- **[components/](./design/components/)** - Component specifications
- **[apis/](./design/apis/)** - API specifications and contracts
- **[database/](./design/database/)** - Database schema design
- **[diagrams/](./design/diagrams/)** - Architecture diagrams and visual documentation

---

### 💻 [implementation/](./implementation/) - Development Agent Output

Generated by `/dev` command. Code and implementation documentation.

- **[plans/](./implementation/plans/)** - Implementation approach and progress tracking
- **[code-records/](./implementation/code-records/)** - Implementation documentation with code snippets
- **[review-guides/](./implementation/review-guides/)** - Code review checklists and QA documentation
- **[integration-guides/](./implementation/integration-guides/)** - Integration and deployment guides

---

### ✨ [review/](./review/) - Review Agent Output

Generated by `/review` command. Quality assurance and compliance verification.

- **[code-reviews/](./review/code-reviews/)** - Code quality and standards compliance reports
- **[design-reviews/](./review/design-reviews/)** - Architecture and design validation reports
- **[requirements-reviews/](./review/requirements-reviews/)** - Requirements coverage and traceability reports

---

### ✅ [testing/](./testing/) - Test Agent Output

Generated by `/test` command. Test planning and test case documentation.

- **[integration/](./testing/integration/)** - Integration test plans and cases
- **[user/](./testing/user/)** - User acceptance test cases
- **[unit/](./testing/unit/)** - Unit test documentation (optional)

## 🔄 Workflow Integration

### Data Flow Between Agents

```
Reference Agent (standards & guidelines)
    ↓ consumed by all agents
Plan Agent → plans/
    ↓ provides context for
SA Agent → analysis/requirements/
    ↓ provides input for
SD Agent → design/
    ↓ provides design for
Development Agent → implementation/
    ↓ provides implementation for
Review Agent → review/
    ├─ if issues found → Development Agent (v2) → iterate
    └─ if approved → continue
Test Agent → testing/
    ↓ provides test results for
Team (approval/merge/deploy)
```

## 🚀 Quick Start

### For AI Agents

Each agent knows where to read input and write output:

1. **Read from** `reference/` for standards and guidelines
2. **Process** according to `.github/agents/[agent-name].agent.md`
3. **Output to** the appropriate folder above
4. **Link** to previous outputs in the workflow

### For Team Members

1. **Establish standards** → `/reference Create [guidelines/templates]`
2. **Plan the project** → `/plan Generate project roadmap`
3. **Analyze requirements** → `/sa Create requirements analysis`
4. **Design architecture** → `/sd Design system architecture`
5. **Implement features** → `/dev Implement [feature name]`
6. **Review quality** → `/review Code review implementation`
7. **Create tests** → `/test Create integration test plan`

## 📖 Documentation Guidelines

- All documents should be **versionable** (include version in filename)
- Use **markdown format** for all documentation
- Include **clear headers** and **table of contents** for long documents
- Add **timestamps** and **author information** when relevant
- Cross-reference related documents using links
